# 与 Gemini 讨论递归语义问题的结论

通过用户指定的供应商 Gemini API，以 `gemini-4-argon` 作为请求模型进行多轮
技术讨论。最初两轮审查混合世界、上下文纤维稳定性和对角化配对；供应商恢复后
继续检查完整表达式指称及开放递归体中的覆盖问题。供应商未返回 `modelVersion`，
此处记录的是请求模型。
请求及答复只用于辅助审查，不能替代 Rocq 证明。密钥没有写入项目。

## 实现进展

后续已完成 add/sub 的完整 context typing，见
[SemanticsAudit.md 的后续实现部分](SemanticsAudit.md)。
实现保留 denotation 和 `CT_Fix`，把候选方案分解为闭合自然数实例的语法归纳、
显式合并条件下的 `CT_FiberCases`、保持结果与终止性的 `CT_Conv`，以及
`CT_ArrowIntro`；三个通用规则的 soundness 已接入 `Fundamental`。
未实现名为 `CT_FixNatCases` 的规则，亦未声称 BST 的组合覆盖已解决。
下面保留当时讨论的建议及其证据范围，不能将其与已经机器检查的实现混为一谈。

## 讨论时的推荐方案

保留现有指称语义和 `CT_Fix`，优先研究新增一个限定于闭合函数的自然数递归规则，
暂名 `CT_FixNatCases`。其递归体在每个固定的当前参数值下分别检查，仍允许下一次
递归实参在整个世界中取不同的、更小的值。

这是一项规则设计建议，尚未加入 `has_context_type`，也没有宣称其 soundness 已由
Rocq 检查。Gemini 在第二轮接受了该路线，但其关于“自动满足侧条件”和 BST 的
部分断言过强；下面给出经过独立复核后保留的结论。

## 原问题的判断

Gemini 同意 [SemanticsAudit.md](SemanticsAudit.md) 的核心分析：混合世界包含零输入
时，普通递归箭头的递减输入前件可能无法满足，使错误的常零函数也真空满足递归
假设。筛掉零输入不是 `⊑` 扩展，不能由 Kripke 单调性继承这个假设。

这指出的是现有规则的递归体前提不足以支持预期推导，并不是现有 `Fundamental`
失效。完整反模型仍未形式化；已检查的相关结论是
`fix_rec_arg_impossible_at_min_zero`。

## 候选规则及充分侧条件

以下为数学层面的规则示意，省略 locally nameless 语法的开闭操作：

```text
对每个 n : nat：
  x : precise{ν = n},
  self : (u : {ν : nat | ν < x} → B[u/x])
  ⊢ body : B[x]

加上闭合性、良构性及 B 的纤维组合条件
------------------------------------------------------
  ∅ ⊢ fix self. λx. body : x : ONat → B[x]
```

其中每个 `⊢ body : B[x]` 都必须是真正的 `has_context_type` 推导。实际代码中应当
沿用 `fix_rec_call_ty` 的输入交类型 `ONat ⊓ {ν < x}`，并正确处理依赖结果的换名。
**不能把递归实参限制成 `u = n`**；固定的是当前参数 `x = n`，递归实参仍为 `u < n`。

初版采用以下保守的充分条件，不声称它们是必要条件：

1. 外部上下文为空，函数闭合；结果类型族只通过函数的参数绑定依赖 `x`。
2. 类型良构、简单类型擦除、局部闭合、变量新鲜性和依赖替换满足既有要求。
3. 对所有合法换名 `z`、合适的类型环境 `Σ` 和良构表达式 `e`，证明
   `ty_denote Σ (B[z/x]) e` 对 `{z}` 具有 `fiberwise_joinable_on`。
   这是类型族的组合性质，不是以目标程序的执行正确性作为类型规则前提。

这里的 `ty_denote Σ (B[z/x]) e` 已经是完整的表达式级指称，包含 guard、
`FTotal` 和函数/基础结果的绑定。不能把条件弱化为仅对结果值上某个 qualifier
的组合性质。恢复后的答复把这个要求称为新的缺口；原先的条件已经包含它，
真正未完成的是证明该条件及其在开闭、换名和环境变换下的适用性。

`∀ n` 是元语言中一族语法推导，不是已经给出了可判定的类型检查算法。

如果以后允许非空 `Γ`，还需证明 `ctx_denote Γ` 沿当前参数纤维稳定。
`Γ ⊫ □Γ` 是可研究的充分条件；不能把它简单等同于某种类型构造子的表面组合。

## Soundness 的证明路线

1. 对自然数 `n` 作强归纳，结论量化所有当前参数恒为 `n` 的合法世界。
2. 为实际不动点函数建立该世界中的递归契约。任取满足 `u < n` 的实参扩展，
   其中 `u` 可以同时取多个值。
3. 按 `u = m` 分成非空纤维。每个出现的 `m` 都小于 `n`，因而可使用归纳假设。
4. 用结果类型族对 `{u}` 的组合性质，把这些纤维的应用结论组合回来，得到整个
   实参世界上的递归契约。
5. 使用第 `n` 个递归体推导的 soundness，并利用 fix 展开的运行语义等价，建立
   实际函数在当前 `x = n` 世界中的结果类型和终止性。
6. 最后按外层 `x = n` 纤维再次组合，得到整个 `ONat` 输入的箭头类型。
   闭合函数值的外层 `□` 再由现有持久类型引入规则处理。

这里只固定递归参数，不把其他 angelic 变量逐一固定。每个参数纤维中仍保留整个
环境集合。新规则的每个前提仍是语法类型推导，新增 Fundamental 分支须独立证明。

## 对 add / sub 的具体意义

当前项目的剩余结果类型族是：

```text
B_add[a] = b : ONat → precise{ν = a + b}
B_sub[a] = b : ONat → precise{ν = a - b}
```

减法在零处截断。这不同于论文 Example 3.3 的 angelic 输入覆盖规约。

可组合性证明预计按如下结构进行：`ONat` 实参类型对 `{a}` 纤维稳定；结果的
over / under 基础类型分别具有组合性质；交类型使用合取的组合引理；普通箭头
还需展开其结果绑定、量化和蕴涵，使用“前件稳定、后件可组合”的引理。

已有基础：`ContextLogic/theories/FormulaFiberwise.v` 的组合框架，以及
`Denotation/theories/TypePersistWandForward.v` 中基础 over / under 类型的组合
引理。但完整的目标类型族组合定理、新规则 soundness、两个递归体推导及最终
`has_context_type` 定理都仍需实际完成。

## 讨论中发现且未采纳的推断

| 推断 | 复核结论 |
| --- | --- |
| 任意 angelic 上下文按新参数取纤维后仍成立 | 错误。例如 `z` 覆盖 `{0,1}`，却与新参数 `x` 完全相关；固定 `x` 可丢失 `z` 的覆盖。 |
| 只要上下文含有 under 类型，就一定不稳定 | 过强。单点 precise 类型的 under 部分不一定依赖跨环境的多个值。 |
| `x▷Rec(x)` 的 Kripke 单调性足以证明修正 Fix 规则 sound | 不充分。还需处理原上下文的纤维稳定性，以及目标类型的组合性。 |
| `□` 可作为任意结果类型的组合归纳步骤 | 错误。`ret x : □ONat` 可在每个单值 `x` 纤维成立，却在 `x` 取多个值的整体世界失败。 |
| 任意普通递归箭头可沿其他变量的纤维继承 | 没有依据。需单独证明，不能由最外层是箭头或函数值就推出。 |
| `⊑` 扩展保证左右子树形成全部组合 | 错误。只保证旧域投影不变，允许对角扩展 `{(L0,R0),(L1,R1)}`。 |

Gemini 第二轮承认了上下文覆盖丢失和 `⊑` 不保证笛卡尔积这两处错误；恢复后的
续谈也接受了表中关于 `□` 不能普遍组合、普通递归契约不能任意切纤维的限制。

## BST 仍然需要的独立证明

候选规则针对当前生成器的闭合递归结构：当前尺寸 `r = n` 固定后，`p` 仍可取
`1..n` 中的多个值，左右尺寸分别是 `p-1` 和 `n-p`，均严格小于 `n`。

不过，完成该 Fix 规则不等于完成 BST 生成器的全部类型推导。至少还需证明：

- `lo : ONat → range : □range_ty → [tree | bst_spec r lo tree]` 对尺寸变量的
  组合性质，包括将 `□range_ty` 作为箭头前件时所需的纤维稳定性。
- 树构造和分支规则能够表达相应的覆盖结论。
- 按每个合法根选择及左子树，覆盖所有合法右子树，最终覆盖所有目标 BST。

最后一项应审查实际求值关系和独立性，而不是假设任意世界扩展都会产生乘积。
项目的 `expr_result_extension_on` 按每个旧 store 收集所有实际可达结果，
`expr_result_extension_witness_on_rel` 约束该精确关系，是可用的证明基础。
它不是确定性假设。不过，这个精确关系本身仍不足以证明任意普通递归假设下的
乘积覆盖，下面的反例说明了原因。

## 普通递归契约与连续两次调用的反例

考虑以下简化类型和两个总函数：

```text
T  = u : ONat → [ν : nat | ν = 0 ∨ ν = 1]
f₀ = λu. 0
f₁ = λu. 1
r  = { [self ↦ f₀], [self ↦ f₁] }
```

按当前 result-first 普通箭头的数学解释，`ret self : T` 可以在 `r` 上成立：
函数求值绑定保留两种函数值；每个满足 `ONat` 的实参扩展仍覆盖两个旧 store；
应用结果合起来覆盖 `{0,1}`。结果 qualifier 不依赖 `u` 或 `self`，没有沿这些
变量分组的额外要求。基础类型和终止性 guard 也不能排除这两个总函数。

然而，对以下程序使用逐 store 的精确求值扩展，结果依然只有对角配对：

```text
let left  = self 0 in
let right = self 0 in
(left, right)

可达结果：{(0,0), (1,1)}
缺少结果：{(0,1), (1,0)}
```

第二次调用虽然不读取 `left`，却读取与 `left` 相关的 `self`。固定 `self` 的纤维
又会使原有的覆盖契约失效。该例是数学层面的语义分析，尚无 Rocq 反模型定理；
它针对“普通契约加精确求值就自动有乘积覆盖”的推断，不是对实际闭合 BST
生成器运行正确性的反例，也尚不是对完整 BST 递归类型和开放体前提的反模型。
Gemini 接受该简化反例后，进一步断言 BST 的完整前提必然失败，超出了反例的
证据范围；本地复核没有采纳该断言。

因此应区分两层工作：先为精确 add/sub 研究 `CT_FixNatCases`；BST 的开放递归体
还需单独处理递归函数与已生成结果之间的相关性。实际闭合函数的求值独立性，
不能直接替代对任意满足递归假设的 `self` 的语法推导。

精确 add/sub 的结果 qualifier 会沿两个输入参数分组，要求每个输入组合的唯一
结果为 `a+b` 或 `a-b`。上述“不同 self 分担不同合法结果”的方式无法伪造这种
精确契约；这并不代替其递归体的正式类型推导。

## 持久递归假设：值得研究的更强变体

另一个候选是把每个固定 `x = n` 前提中的 `self : Rec(x)` 改为
`self : □Rec(x)`，仍保留结果类型族的表达式级组合条件。
这项变体尚未实现，也未完成 soundness 证明。

不能仅凭“函数闭合”就对任意依赖契约引入 `□`。当前候选还有一个关键条件：
在第 `n` 个递归体前提中，旧参数 `x` 已经恒为 `n`。若 `B` 没有其他自由参数，
实际闭合函数 `F` 的递归契约在函数结果绑定后，其相关自由变量仅为 `x` 和绑定的
函数值 `f`。两者分别恒为 `n` 和 `F`，所以它们的投影为单 store。

可研究的充分证明路线是：先用上述强归纳及组合引理，证明普通 `Rec(x)` 在所有
`x = n` 的合法世界成立；再把该结论实例化到 `{x ↦ n, f ↦ F}` 的单 store 世界，
通过 `res_models_persist_intro` 和 `CTPersist` 的结果绑定建立实际函数的
`□Rec(x)`。这一步需要实际证明：

- 递归契约、相关 guard 的自由变量与环境限制满足预期；
- 单 store 投影良构，`x=n` 与闭合函数的结果绑定在投影后仍成立；
- 普通递归契约的结论对所有额外世界变量、换名和替换统一；
- 固定点展开、终止性及相关的类型/世界 guard 均可传递。

其中自由变量控制已有机器证明的基础：`TypeDenoteRegular.v` 中
`ty_denote_gas_fv_subset` 给出完整指称的自由变量包含于 `fv_tm e ∪ fv_cty τ`，
`ty_denote_gas_minimal_on` 给出向这组变量投影的等价性。应用到具体递归契约、
处理绑定换名并建立单 store 见证的工作仍待完成。

本项目的 `□` 要求相关自由变量上的投影本身是单 store，不只是“所有子世界上
都成立”。不能省略这个条件。这条证明路线没有对正向的 `□B` 假定组合性质；
`□Rec(x)` 在这里是提供给递归体使用的假设。

即使该变体最终 sound，BST 仍需树构造、分支和精确结果扩展的组合证明。
目前不能把它称为已经足够推导整个 BST 程序的规则。固定了 `left` 的分支不可能
单独覆盖原规约中所有不同的左子树；需要先明确相应条件规约，再完成组合推导。

恢复后的答复还一度把 `□` 描述为“任意子世界都成立”，并断言加强递归假设后
就彻底解决 BST。这不符合 `FormulaSemantics.v` 的实际定义，也省略了上述组合
义务；已据源码再次追问，但该次请求在 480 秒后读取超时，未取得确认答复。
这里关于实际 `□` 定义及单 store 投影的修正来自本地源码复核，不能将 Gemini
的前一段答复作为证明。
