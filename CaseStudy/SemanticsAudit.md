# 箭头与递归的指称语义审查

审查对象：本地论文 *Context Types: Bunched Modalities for Unifying Safety and
Reachability*（2026 年 7 月版）第 10、12、14–17、19–21 页，以及当前项目中的
`CTArrow`、`CT_Fix` 和世界扩展定义。原有指称语义和 `CT_Fix` 保持不变；后续实现见文末。

## 结论与证据范围

导致算术类型推导受阻的关键定义与论文正文一致：世界非空，Kripke 扩展保留旧变量
上的整个环境集合，普通箭头在整个当前能力上检查实参。因而，仅把实现的箭头公式
改回论文第 17 页的写法不能解决问题。

下面给出一个数学反例，说明论文 Example 3.3 所声称的 **T-Fix 前提** 在正文语义的
字面解释下存在问题。它不是对 T-Fix 规则 soundness 的反例，也不是对减法程序
运行正确性的反例。当前 `Fundamental` 的证明并未因此失效：它仍要求先给出合法的
类型推导，不能凭程序的运行正确性跳过递归体前提。

Rocq 已检查的事实是 `fix_rec_arg_impossible_at_min_zero`：最小参数度量为零的世界，
在任何 Kripke 扩展中都没有满足严格递减规约的实参。下文关于常零函数和整个递归体
前提的分析是展开论文定义后的数学推演；尚未编码成完整的 Rocq 反模型定理。

## 混合世界为何使递归假设失去约束

为避免同名绑定混淆，用 `x` 表示当前调用的第一个参数，用 `u` 表示下一次递归的
第一个参数。递归函数的输入规约是：

```text
u : {ν : nat | True ∧ ν < x}
```

取总函数 `f₀ = λu. λv. 0`，以及如下能力：

```text
r = { [x ↦ 0, self ↦ f₀],
      [x ↦ 2, self ↦ f₀] }
```

若 `r ⊑ r'`，旧环境 `[x ↦ 0, self ↦ f₀]` 必须仍有扩展。任何绑定了自然数实参
`u` 的这种扩展，都不可能在该环境中满足 `u < 0`。所以不存在覆盖整个 `r` 且满足
递减输入规约的实参能力。这里说的是 **在这个世界上没有可接受的实参扩展**，不是
说 `{ν | ν < x}` 在所有世界中都为空：固定 `x = 2` 时，它当然允许 `0` 和 `1`。

普通箭头的行为条件为“实参满足输入规约，则应用满足输出规约”。在上述混合世界及
其扩展上，前件无法成立，因此该条件真空成立。`f₀` 是类型正确的总函数值，故也能
满足这个递归箭头的 guard；其错误的递归计算结果没有受到行为条件的约束。

现在只保留 `x = 2` 的环境，得到 `r₂`。这次 `u = 1` 是合法的递归实参，常零函数
通常不满足精确算术输出规约。关键是：

```text
r₂ ⊆ r，但 r ⊑ r₂ 不成立。
```

Kripke 单调性只允许沿 `⊑` 传递成立性，不能用来把递归函数的类型从 `r` 搬到
`r₂`。普通函数类型也没有一般的“删掉部分环境后仍成立”性质。

## 对 add / sub 精确规约的影响

在 `CT_Fix` 的递归体前提中，用上面的 `f₀` 解释 `self`：

| 递归体 | 当前参数 | 递归调用 | 实际结果 | 精确规约要求 |
| --- | --- | --- | --- | --- |
| `add` | `x = 2, b = 0` | `f₀ 1 1` | `0` | `2` |
| `sub` | `x = 2, b = 1` | `f₀ 1 0` | `0` | `1` |

这分析的是一个任意递归假设下的开放递归体。实际闭合的 `add_value`、`sub_value`
把 self 绑定为各自的真正不动点，其全输入执行正确性和终止性已经另外证明。

因此，不能从已经证明的执行正确性直接宣布 `CT_Fix` 的递归体前提成立。
`CT_CtxCases` 本身是 sound 的有限逻辑分类规则，但分类要求每个备选上下文在
**整个待检查世界** 上成立；它不会自动把世界拆成单个环境，也不会补强已经
真空成立的递归假设。

## 与论文 Example 3.3 的张力

论文第 12 页的目标是覆盖规约，而不是项目中的精确减法规约：

```text
x : {ν : nat | True} → y : [ν : nat | ν ≤ x] → [ν : nat | ν ≤ x]
```

同样取混合世界 `r` 和常零递归函数 `f₀`。递归函数的首个输入要求 `u < x`，
所以它在 `r` 上的行为条件仍然真空成立。对待检查的 `λy` 取下面的实参扩展：

```text
(x, y) = (0, 0), (2, 0), (2, 1), (2, 2)
```

每个 `x` 的纤维中，`y` 都覆盖 `0..x`，符合输入的 angelic 规约。开放递归体的结果为：

| `x` | `y` | `if x=0 then 0 else if y=0 then x else f₀ (x-1) (y-1)` |
| --- | --- | --- |
| 0 | 0 | 0 |
| 2 | 0 | 2 |
| 2 | 1 | 0 |
| 2 | 2 | 0 |

在 `x = 2` 的纤维中，结果只有 `{0, 2}`，缺少规约要求覆盖的 `1`。
因此，按照正文定义逐项解释，Example 3.3 列出的递归体前提不能由其文字说明直接
成立。第 21 页先绑定函数求值结果的广义箭头定义也不会排除本例，因为 `f₀` 及
这里的 lambda 都是确定的函数值。

这个例子提示需要核对论文是否省略了额外规则或递归假设的局部化条件。本次只审查
了给定 PDF 正文，没有据此断言补充材料采用了何种定义。

## 后续实现：add/sub 的完整 typing 已完成

`CaseStudy/theories/NatArithmeticTyping.v` 中的
`add_value_context_typed` / `sub_value_context_typed` 是原始
`add_context_ty` / `sub_context_ty` 的完整 `has_context_type` 定理，包含 `□`。

实现保留原有 denotation 和 `CT_Fix`，没有把混合世界上的递归假设视为逐 store
稳定。实际采用三个通用规则：

1. `CT_Conv`：从已有语法类型推导搬运类型，要求在每个上下文模型中同时保持
   每个 store 的结果集合和 must termination。它不允许从任意运行证书直接赋型。
2. `CT_FiberCases`：每个输入纤维必须满足某个已检查的上下文，擦除环境相同，且
   **目标 denotation 明确可合并**。这里用输入自然数对索引分类，只对精确自然数
   结果证明合并性质；没有对普通箭头或含 `□` 的任意结果作此假定。
3. `CT_ArrowIntro`：从对每个新参数的应用类型推导，引入函数值的普通箭头。
   soundness 显式处理函数结果绑定、参数量化以及 guard。

`NatArithmeticInstances.v` 对第一个自然数输入归纳，第二个输入始终任意。
每个实例从常量规则、较小实例的类型推导和有限确定性化简构造，独立于
`add_value_run` / `sub_value_run`。实例先搬运到固定输入的上下文，证明精确
qualifier 的子类型，再由纤维分类合并。最后封装两个箭头和持久类型。
额外世界变量保留在各纤维中，没有把 Kripke 投影扩展当成笛卡尔积。

三个规则的 soundness 已接入 `Fundamental`。这条路线将原计划中的逐自然数递归
检查分解为已有 Rocq 自然数归纳及通用规则，未加入候选的 `CT_FixNatCases`。
这只解决算术库函数；BST 的左右子树组合覆盖和完整 typing 仍是独立义务。

`Print Assumptions` 对两个 typing 定理和 `Fundamental` 输出相同的既有假设：
经典排中律、经典不定描述、函数外延性、命题外延性和证明无关性。
没有新增公理或 `Admitted`。
